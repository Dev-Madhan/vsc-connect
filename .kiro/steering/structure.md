# Project Structure

## Top-Level Layout

```
app/              # Next.js App Router — routing only, no business logic
components/       # Shared, reusable UI components
lib/              # Core utilities, auth, RBAC, Prisma client, error types
lib/services/     # Business logic services (static class pattern)
lib/validations/  # Zod schemas (one file per domain)
services/         # Top-level infrastructure services (email, storage, novu)
prisma/           # schema.prisma, migrations/, seed.ts
docs/             # Architecture and engineering documentation
public/           # Static assets
```

## `app/` — Routing Layer

Follows Next.js App Router conventions. Route folders map directly to URLs.

```
app/
  layout.tsx              # Root layout
  page.tsx                # Homepage (public)
  globals.css             # Global styles
  login/page.tsx          # Login page
  dashboard/              # Protected admin/member dashboard
    events/
    gallery/
    members/
    od-documents/
    settings/
  api/auth/[...all]/      # Better Auth catch-all route handler
  about/
  contact/
  events/
  gallery/
  news/
  projects/
  recruitment/
  sub-clubs/
```

- Pages are Server Components by default
- Add `"use client"` only when browser APIs or interactivity is required
- No business logic in pages — delegate to services or server actions

## `components/` — UI Components

```
components/
  ui/           # shadcn/ui primitives (button, card, input, label, etc.)
  *.tsx         # Shared feature-level components (e.g. login-form.tsx)
```

- Component files: `PascalCase.tsx`
- Use `cn()` from `@/lib/utils` for all className composition
- Keep components presentation-only; no direct Prisma or service calls

## `lib/` — Core Infrastructure

| File | Purpose |
|---|---|
| `auth.ts` | Better Auth server instance |
| `auth-client.ts` | Better Auth browser client |
| `prisma.ts` | Singleton Prisma client (pg pool adapter) |
| `rbac.ts` | `getSession`, `requireAuth`, `requireRole`, permission helpers |
| `env.ts` | Type-safe env vars via `@t3-oss/env-nextjs` |
| `errors.ts` | Custom error classes (`APIError`, `ValidationError`, `NotFoundError`, etc.) |
| `audit.ts` | `logAuditAction()` — never throws, fire-and-forget |
| `utils.ts` | `cn()` and general utilities |

## `lib/services/` — Business Logic

Static class pattern. One file per domain.

```
member.service.ts
event.service.ts
club.service.ts
content.service.ts
document.service.ts
```

Service rules:
- All business logic lives here — not in pages, not in components
- Always validate input with Zod before processing
- Throw typed errors from `lib/errors.ts` (`NotFoundError`, `ConflictError`, etc.)
- Use `prisma` from `@/lib/prisma` — never instantiate Prisma elsewhere
- Call `logAuditAction` for sensitive mutations
- Use Prisma transactions for multi-step writes

## `lib/validations/` — Zod Schemas

One schema file per domain, co-located with inferred TypeScript types.

```
member.schema.ts
event.schema.ts
club.schema.ts
content.schema.ts
document.schema.ts
```

Pattern:
```ts
export const createXSchema = z.object({ ... });
export type CreateXInput = z.infer<typeof createXSchema>;
```

## `services/` — Infrastructure Services

Top-level singleton service modules for external integrations.

```
storage.ts   # Cloudflare R2 upload/delete/presigned URLs
email.ts     # Resend email sending
novu.ts      # Novu notification triggers
```

## `prisma/`

```
schema.prisma   # Single schema file — all models and enums
seed.ts         # Initial seed: Club, Roles, SuperAdmin, SubClubs, Settings
migrations/     # Auto-generated by prisma migrate dev
```

Schema conventions:
- All PKs: `String @id @default(uuid())`
- All models include: `createdAt`, `updatedAt`, `deletedAt?`, `createdBy?`, `updatedBy?`
- Soft delete via `deletedAt DateTime?` — filter with `deletedAt: null`
- Media (images, PDFs): store URL only, never binary

## Path Aliases

`@/*` maps to the project root. Always use aliases, never relative paths.

```ts
import { prisma } from "@/lib/prisma";
import { MemberService } from "@/lib/services/member.service";
import { Button } from "@/components/ui/button";
import { env } from "@/lib/env";
```

## Naming Conventions

| Thing | Convention |
|---|---|
| React components | `PascalCase` |
| Non-component files | `kebab-case` |
| Service classes | `PascalCase` static class |
| Hooks | `useSomething` |
| Zod schemas | `camelCaseSchema` |
| Inferred types | `PascalCase` (via `z.infer`) |
| Constants | `UPPER_SNAKE_CASE` |
| Git branches | `feature/`, `fix/`, `refactor/` prefix |
